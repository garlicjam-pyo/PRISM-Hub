# 최종 보고서 작성용 정리(report-prep 브랜치)

최종 보고서(11월 말, LaTeX)를 쓸 때 **어느 장에 무엇을 쓰고, 그 수치·그림·판정이 어디서 왔는지**를 한곳에서 확인하도록 정리한 폴더다. 새 검증이나 수치는 없다. 모든 내용은 `final-report` 브랜치의 문서와 검증 기록을 옮기거나 가리킨다. **2026-10-29 갱신**: E30–E37·TB24–TB29와 검증 정리(이전 문서 정정, docs/20 최종판)를 반영해 다시 만들었다(처음 판은 `eae5863`, E29·TB23까지). 같은 날 외부 검토 대응과 남은 설계 과제의 설계 변경(E38·TB30·TB31, docs/43)을 반영했다.

- 수치를 고칠 때는 이 폴더가 아니라 **원문(docs/, validation/, simulink/)을 고치고** `02`·`06` 부록을 다시 생성한다.
- 정식 보고서에는 저장소 URL·경로를 쓰지 않는다. 이 폴더의 링크는 작성자가 근거를 찾기 위한 것이다.

## 다시 만들기

저장소 최상위에서:

```
python report_prep/tools/build_index.py   # 02_검증_현황표.md, 06_그림_목록.md 부록
python report_prep/tools/build_notion.py  # notion/PRISM-Hub_보고서_정리.md(01–07을 한 페이지로, 링크는 글자만)
python report_prep/tools/check_links.py   # 깨진 링크가 있으면 목록을 출력하고 1로 끝남
```

`build_index.py`는 docs/20 6절 "검증 결과 이력" 표와 simulink/README.md의 "테스트벤치 진행 상태" 표를 읽는다. 두 표의 열 구성을 바꾸면 스크립트도 고친다.
