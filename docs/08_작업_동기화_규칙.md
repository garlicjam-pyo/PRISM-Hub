# 두 컴퓨터 작업 동기화 규칙

현재 작업 브랜치를 양쪽 컴퓨터에서 동일하게 사용한다. `main`만 최신이라는 가정은 하지 않는다. 후속 개발은 `codex/review-response-integration`에서 진행되며, README와 실행 결과를 함께 확인한다.

## 도우미 동작

- 시작: `./tools/sync.ps1 start` 또는 `./tools/sync.sh start`. 작업 트리가 깨끗한지 확인하고 현재 브랜치의 원격을 fast-forward로 받는다. 원격에 아직 없는 새 브랜치는 fetch만 한다.
- 종료: `./tools/sync.ps1 end "message"` 또는 `./tools/sync.sh end "message"`. **현재 작업 트리 전체를 add -A**하여 변경이 있을 때 커밋하고, 같은 원격 브랜치 위로 rebase 후 `HEAD`를 그 브랜치에 push한다. 실행 전에 `git diff`와 `git status`로 대상 파일을 확인한다.
- Git 명령이 실패하면 중단한다. detached HEAD, 미해결 충돌, 진행 중 rebase에서도 중단한다. 빈 변경으로 종료해도 이미 생성된 커밋은 push할 수 있다.
- 개발 브랜치에서 `main`을 암묵적으로 push하지 않는다. 이 수정 전 v0.9 helper는 main을 고정 참조했으므로 사용하지 않는다.

## 첫 번째 컴퓨터에서 새 브랜치를 받은 뒤

다른 컴퓨터에서는 `git fetch origin` 후 `git switch --track origin/codex/review-response-integration`로 최초 연결한다. 이미 브랜치가 있으면 `git switch codex/review-response-integration` 후 `start`를 사용한다. 미커밋 작업은 먼저 보존한다.

## 저장 대상과 실행 기록

코드, 문서, 생성 스크립트, 요약 JSON, 검토에 필요한 그림·SLX를 커밋한다. MAT 대용량 로그, `slprj/`, 캐시, autosave는 제외한다. 검증 결과는 **모델/날짜별 별도 폴더**에 두고, 이전 독립 검토·결과를 새 결과로 덮어쓰지 않는다. 같은 조건의 회귀시험 재실행은 기존 폴더에서 허용하되 변경된 의미를 감추지 않는다.

변경 후 README, CHANGELOG, EXECUTION_LOG와 관련 문서를 갱신한다. 새 모델이 생겨도 예전 파일을 모두 검증 완료로 표시하지 않는다. 충돌이 생기면 모델의 가정·증거를 비교해 해결하고, JSON은 단순히 최신 날짜라는 이유로 선택하지 않는다.
