# 두 컴퓨터 작업 동기화 규칙

GitHub(`origin/main`)가 유일한 진실이다. 로컬은 어느 쪽이든 임시본이며, 세션은 반드시 `pull`로 시작하고 `push`로 끝낸다.

## 세션 루틴
1. 시작: `.\tools\sync.ps1 start` (Windows) / `./tools/sync.sh start` (macOS·Linux) — 원격 최신을 fast-forward로 받는다. 커밋 안 된 변경이 있으면 중단하고 알려 준다.
2. 작업.
3. 종료: `.\tools\sync.ps1 end "메시지"` — `add -A` → commit → `pull --rebase` → push. 짧게라도 반드시 실행한다(다른 컴퓨터에서 이어가려면 원격에 있어야 한다).

## 무엇을 커밋하나
- 커밋: 문서(docs/), 스크립트(matlab/, python/), 결과 요약 JSON(python/results/), 그림(docs/fig/), README·CHANGELOG·EXECUTION_LOG.
- 커밋 안 함(.gitignore): `*.mat`, `slprj/`, `*.asv`, `*.slx.autosave`, `__pycache__/`. Simulink 모델 `.slx`는 **커밋한다**(바이너리, `.gitattributes`로 지정) — 단 생성 스크립트(`build_rsc_phase.m`)로 재생성 가능한 모델은 스크립트를 진실로 보고 `.slx`는 결과물로 취급.
- 대용량 로그(`.mat` 수십 MB)는 커밋하지 않고, 요약 수치를 JSON/문서에 옮긴다.

## 문서 갱신 규칙 (어느 컴퓨터에서든 동일)
- 검증 하나가 끝나면: README 4절 표에 한 행, 8절 다음 단계 갱신, `logs/EXECUTION_LOG.md`에 세션 항목 추가, 설계가 바뀌면 README 5절 + CHANGELOG 버전 증가.
- 설계검증서(docs/02)는 부록에 결과를 붙이고, 본문 결론이 바뀌면 해당 절을 고치고 9장 정정표에 번호를 추가한다.

## Claude와 이어갈 때
새 대화에서 "PRISM-Hub 저장소 최신에서 이어서"라고 하면 README·EXECUTION_LOG·CHANGELOG를 기준으로 상태를 복원한다. 로컬에서 나온 MATLAB 결과는 수치·그림을 대화에 붙이거나 `python/results/`·`docs/fig/`에 커밋해 두면 그대로 이어 분석한다.

## 충돌 시
같은 파일을 두 컴퓨터에서 고쳤다면 `pull --rebase`에서 충돌이 난다. 문서는 양쪽 내용을 합치고, 결과 JSON은 최신 실행분을 남긴다. 해결 후 `git rebase --continue` → push.
