## 1. H2 판정 정정(h2)

평균모델은 리플·감지 여유를 뺀 전류 기준(Tier-1 90 A, Tier-2 93.75 A)을, 스위칭 모델은 리플을 포함한 순시전류 기준(Tier-1 98 A, Tier-2 100 A)을 쓴다. 같은 128개 복합 공차 조합(7개 파라미터 각각 ±10 % 끝값)이 두 기준에서 다르게 판정되었다.

| 640 V 시험 | 기준 | 결과 |
|---|---|---|
| E5 평균 단일 공차 격자(632–920 V) Tier-1 / Tier-2(추가 지연 제외) | 90 / 93.75 A | 460/460 · 78/78 |
| E5 Tier-2 +3 µs 정보 시험 | 93.75 A | 13/14(632 V 경계 94.08 A, 640–920 V 12/12) |
| E7 복합 Tier-1 15 → 25 kW, 추가 3 µs | 90 A | 128/128, 최대 89.08 A |
| E7 복합 Tier-2 1 → 25 kW, 추가 0 µs | 93.75 A | **102/128**, 최대 95.82376 A |
| E7 L\_h ±5 % 재시험(실패 26건) | 93.75 A | 18/26, 최대 94.33 A |
| E12 스위칭 복합 Tier-2 | 100 A 순시 | 128/128, 최대 97.32 A |

H2의 수락 조건(두 기준 동시 충족)을 유지하므로 H2는 **부분 충족**이다. E11에서 독립 구현한 두 코드의 통과·실패 판정은 이 실패를 포함해 일치했다(MATLAB 형식 코드의 실행 환경은 GNU Octave 8.4).

## 2. 클램프 지연·P5·제동 펄스열(delay·p5·brake)

- **판정 범위.** E44 K1(공통 오차: 사양 팩 0·+0.025·+0.05·+0.075·+0.10 %, W460 0 … +1.0 %를 0.25 % 간격)과 K2(폭 6.0·4.5·4.0·3.5·3.0 V)는 이산 탐색, K3는 지정 끝값의 결합 모서리다. 모두 켬·끔 지연 각각 1.0 µs 고정이다. 연속 범위 전체의 통과를 보인 것이 아니다.
- **지연 반례(D1·D2).** K3 지정 모서리(사양 팩 +0.075 %·3.5 V·P−, W460 +1.0 %·4.0 V·P−, 모두 작은 저항)의 모든 사건(64·32건)에서 온도가 가장 높은 세 사건을 다시 계산했다.

| 사양 팩 640 V R2 경로 상실·정지까지 전류 유지(간격 0.0625 µs) | 켬 횟수 | 선정식 환산온도 |
|---|---|---|
| 지연 1.0 µs, 폭 3.5 V | 672 | 148.07 °C(통과) |
| 지연 0.5 µs, 폭 3.5 V | 704 | **151.26 °C(초과)** |
| 지연 0.5 µs, 폭 4.0 V | 622 | 143.01 °C(이 사건에서 통과) |

간격 0.25 µs에서 0.5 µs·3.5 V는 150.76 °C, 0.03125 µs에서 151.57 °C다. 지연 1.0 µs는 0.03125 µs 간격에서도 148.30 °C(사양 팩)·143.18 °C(W460)로 통과했다. W460 4.0 V는 0.5 µs에서도 최대 145.84 °C로 통과했다. 실제 검출·구동 회로의 지연 하한·상한과 폭은 함께 정하고 검증해야 하며, 4.0 V 한 점의 성공으로 폭을 확정하지 않는다.
- **P5.** 선정식 환산온도 = 사건의 도통·스위칭 에너지를 첫 켬부터 마지막 끔까지의 시간으로 나눈 평균손실 × 선정용 정상 열저항 + 기준 온도. 공칭 문턱·수동소자: 사양 팩 125.10 °C(481.5 W, 스위칭 74 %), W460 124.86 °C(479.7 W). 지정 모서리: 147.64 °C(662.2 W, 81 %), 142.58 °C(621.6 W, 80 %). 전압·전류·에너지·온도의 최댓값은 서로 다른 사건에서 나올 수 있다. 대체 CAB530M12BM3의 131.4·131.1 °C는 공칭 계산이다. 0.037 V와 2.36 °C는 기존 0.25 µs 시간 격자에서 한도와의 차다.
- **P8.** R2-W460 240s 930 V H-브리지 개방 고장 강등(감발 메시지 모두 손실, Stage C 일시 정지)에서 제동 에너지 51.875 J는 약 57.5 ms에 걸친 30회 펄스(첨두 3.34 kW)의 합이다. 반복 주기와 열누적은 제조사 확인 대상인 조건부 후보로 둔다.

## 3. 실행 방식과 재현(repro·fcheck·dstrict)

- **원인.** E44 F-b → E35 과도·E33 고장, E35 → E34 단일 클램프, E36 → E16 충전기 과도는 부모 프로세스에서 설계값(C\_fly·C\_A·R\_A)을 바꾼 뒤 작업자를 띄운다. Windows·macOS의 `spawn`과 Python 3.14 이후 Linux 기본 `forkserver`는 자식에서 모듈을 새로 읽어 이 값을 잃는다.
- **고침.** 모든 병렬 실행(multiprocessing Pool 28개 스크립트, ProcessPoolExecutor 5개 스크립트)을 `common.Pool`·`common.Executor`로 바꿨다. fork가 있으면 fork 문맥을 명시하고, 없으면 같은 프로세스에서 차례로 실행한다(`PRISM_POOL=fork|serial`). 클램프 사건은 C\_A를 사건 인수로, E16 충전기 모델은 모듈당 저항을 객체에 저장해 V\_A 후처리까지 같은 값을 쓴다. 플랜트 C\_fly는 제어 타이밍(45.0 µF 기준 25,515.63 Hz)과 따로 `model_stage_a.PLANT`로 준다(F-b 플랜트 공진 26,178.48 Hz).
- **대표 다섯 사례(S1, 같은 프로세스 차례 실행 `PRISM_POOL=serial`, Windows와 같은 경로).** 11개 값이 저장 결과(fork 실행)와 모두 같았다(상대 차 0).

|---|---|---|
| E44 MA10 540 V 위상 첨두, F-a(45.0 µF) / F-b(42.75 µF) | 55.64694 / 55.60202 A | 같음 |

- **F 56행(S2).** 고친 코드로 E44 cfly(F-a 45.0 µF·F-b 42.75 µF, 요구 안 과도 12건·모듈 고장 16건씩)를 fork 실행으로 다시 계산했다(F-a 1,680 s, F-b 1,634 s, 둘 다 12/12·16/16 통과, 첨두 76.1·106.2 / 74.4·106.9 A). F-b는 제어 25,515.63 Hz, 플랜트 26,178.48 Hz로 기록되었다. 1차 판정은 **실패**로 나왔는데, 판정 코드가 직렬화 전 객체(정수 키·튜플)를 JSON에서 읽은 저장 결과(문자열 키·리스트)와 비교해 형 차이(과도 112개·고장 8개씩)만 잡았기 때문이다(`fcheck_run1_serialization_failed.json`). 판정 기준(엄격 비교 차 0)은 그대로 두고 비교 경로를 저장 결과와 같은 save_json → load_json으로 고쳐, 다시 계산하지 않고 저장된 새 결과로 다시 판정한 결과 56행 모두 차 0이었다(`fcheck.json`, `run_fcheck_rejudge.log`).
- **엄격 비교(dstrict).** `common.strict_diff`(키 집합·배열 길이·문자열·불리언·NaN·유한 수, 수치 허용 10⁻⁶ × max(1, |x|), 실행시간 필드만 제외)의 자체 시험(키 삭제·문자열 변경·NaN·길이·불리언·수치·형 변경은 실패, 같은 값은 통과) 8종을 통과했고, E44 D의 저장 비교 7쌍(E38 l1 세 가지, E41, E42 cases·cells, E43 loss)을 이 비교기로 다시 비교해 차 0이었다.
- **입력 출처.** E44 scope는 기본으로 저장 자료(`"source": "archived"`)를 읽고, `PRISM_SOURCE=fresh`이면 이번 실행의 results/(E8·E35·E36·E38)를 읽어 `scope_fresh.json`에 쓴다. 입력마다 경로·종류·SHA-256·바이트 수를 남긴다. H4의 미공급 6.96 % < 정적 예약 35.21 %를 직접 검사한다.
- **실행기.** 자식 스크립트와 작업 폴더는 실행기 위치 기준, 없는 스크립트·알 수 없는 근거 번호는 오류, 자식 실패는 비정상 종료. E44 순서는 scope·dev·bkv·clamp·cfly, E45 단계를 더했다. 클램프 재개는 코드·입력·문턱·사건·간격의 해시가 같을 때만 한다.
- **실행 경과.** 긴 부분 1차 실행(`run_long1_repro_import_failed.log`)은 delay·p5·brake를 마친 뒤, 실행 중에 E16의 병렬 실행기를 `common.Executor`로 바꾼 커밋 때문에(이미 읽어 둔 이전 common에 Executor가 없음) repro에서 ImportError로 멈췄다. repro·fcheck만 새 프로세스로 다시 실행했다(`run_long2.log`).

- **초록·범위:** 대상 차량, 모델 정정과 설계 변경 구분, 12 V(48 V에서 파생하는 부하, 독립 12 V 단자 조정 미시험), 90개 후보(소자 구성 15 × 공진주파수 6, 150·100 kHz의 30개 모두 불성립), 사전 기록(E30 이후 / E26–E29·TB21–TB23), 표준 범위, TB 수 기준.
- **조판:** 7장·20장의 강제 쪽 높이 확대 두 곳을 지웠다. 보고서와 논문의 모든 쪽에서 본문 아래 끝과 쪽 번호의 간격을 확인했다(5절).

## 5. 남은 일

- 논문 첫 쪽의 저자 세 명, 지도교수, 대학·학과를 제출자가 공식 표기로 입력한다(‘○○○’).
- 실제 지연 범위를 주장하려면 새 시험 번호에 켬·끔 지연의 하한·상한·상관과 판정 기준을 먼저 기록하고, 두 지연을 독립 입력으로 두 팩의 사건·가지저항·문턱 오차·폭·수동소자 공차(독립 공차면 32개 끝값 조합과 경계 인근 내부)와 교차한다.
- 180s의 48 V 서비스(최저 입력 268.77 V에서 정방향·회생·듀티 한계·전압 품질·스위칭 조건).
- 전체 E1–E45와 Simulink 전체의 새 일괄 실행, Windows 실기에서의 실행 확인(이번에는 같은 프로세스 실행 경로를 Linux에서 확인).
